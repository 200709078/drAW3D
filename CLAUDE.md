# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

drAW3D is a 3D geometry and net (açınım) app (Three.js, TypeScript + Vite) shipped as a web app and an Electron desktop app (Linux AppImage/deb, Windows NSIS); Android/iOS packaging (Capacitor) comes later. It is the sibling of drAW2D (`../drAW2D`) and shares its shell, toolbar and conventions. The UI, test names, docs (README, `docs/*.md`) and messages are in **Turkish** — keep new user-facing strings and docs in Turkish.

## Commands

Node >= 22.12 (`.nvmrc`: 22).

```bash
npm ci
npm run dev              # Vite dev server
npm run typecheck        # tsc for src/ and for electron/ (tsconfig.electron.json)
npm run build            # typecheck + compile electron shell + vite build → dist/, dist-electron/
npm test                 # Playwright (Chromium, WebGL on SwiftShader); starts Vite on 127.0.0.1:4173
TEST_PREVIEW=1 npm test  # same tests against built dist/ via vite preview (run build first)
npx playwright test tests/app-tools.spec.ts               # single file
npx playwright test -g "açınım"                           # single test by title
npm run electron:dev     # Electron against the Vite dev server
npm run test:electron    # build, then open the app from file:// and check it (needs a graphical session)
npm run dist:linux | dist:win
```

## Architecture

Dependencies point one way: `geometry` → `document` → `rendering` / `app` → `ui`. `geometry/` and `document/` know nothing about the DOM or Three.js; geometry code must not depend on Electron either.

- `src/geometry/`: `vec3.ts` plain `{x,y,z}` vectors and ray helpers. `types.ts` the object models: plain structured-cloneable data referencing other objects by ID (`points`, `constraint.ownerId`, `ownerId` for helpers). Optional fields (`hidden`, `geometryValid: false`, style fields) are absent by default so reverting restores the exact graph. `solids.ts` computes shapes from positions (line, plane, angle, sphere, prism/pyramid from base edge AB + side point C + side count + height, cylinder/cone from base center + rim point + height; `topRatio` 0–1 turns a pyramid/cone into a frustum / cut cone), areas and volumes. `polyhedra.ts`: the five regular solids (`regular` objects) built on edge AB, base face first, vertices A, B, base face, rest (locked `corner` vertex points use these indices). `parts.ts`: every shape has an ordered list of parts (edges = curves, faces = surfaces) with their own parameter space (`position`, `project`, `tangents`, `samples`, `fromRay`); a point on an object stores only `{ ownerId, part, params }`. `nets.ts`: every polyhedron opens along a face tree (`unfoldTree`: prism/frustum sides on the base, top on the last side; pyramid sides on the base; the cube one of its 11 nets from `cubeNets`, chosen by `net` 0–10; other regular solids breadth first); each hinge turns at most until its face reaches its parent's plane. `unfold.ts` builds nets as pure data and owns `maxUnfoldAngle`: the cylinder/cone side bends flat (curvature/half angle change, arc length kept); a cut cone opens as a band of its full cone with the top disk on the inner arc. `net-sheet.ts` lays the fully opened net flat in 2D (cut lines, fold lines, optional glue tabs) for printing. `section.ts`: a solid or sphere cut by a plane (`section` objects). `tests/geometry-unfold.spec.ts` checks flatness, area and edge-length invariants — keep it passing. `measures.ts`: length, distance and acute angle between points/lines/rays/segments/planes, base area, surface area and volume (pure). Besides figures there are `parameter` objects (`a=2`, slider bounds) and `measure` objects (`Hacim(prizma1)`, value computed from targets). A number field may come from an expression over parameters: `definition` maps the field (`x`, `y`, `z`, `radius`, `sideCount`, `height`, `unfold`, `value`) to its expression. A sphere is either center + surface point or center + `radius` (then a purple size handle sits on top). `derived.ts`: constructed points (`constraint.type === 'construct'`: midpoint, intersection, projection, and for constructed lines/planes the internal `along`/`basis`/`planeMeet` points); a line or plane built from other objects keeps `construction` for its text, and its extra points are internal helpers (`isInternalPoint`: owned construct points, never drawn, picked, labeled or listed). `visibility.ts`: which solid edges a viewer sees (convex: an edge is hidden when both faces turn away), cylinder/cone circle pieces and silhouettes.
- `src/commands/`: the input language. `language.ts` is the single table (command names and aliases, `<Placeholder>` templates, help topics and examples); add a command there first. `parser.ts` parses a line into `{ name, command }` (`A=(1,2,3)`, `s: DoğruParçası(A,B)`, `a=2`, `Kesiştir(d,p)`); numbers are constants or `{ expression }`. `expressions.ts` checks math.js 15.2.0 syntax trees (scalar arithmetic, listed functions, e, pi, parameter names only) and evaluates them; `src/math.ts` configures math.js like drAW2D (pinned, custom `log(base, value)`). `prepare.ts` builds a command's objects against a snapshot **without mutating the document** — a failing command consumes no IDs, names or history. `describe.ts` gives each object its defining command text (`definitionText`, `editLine`), which parses back to the same object.
- `src/document/`: `geometry-document.ts` (same core as drAW2D) owns membership, selection, monotonic IDs (never reused), drafts (half-finished tool drawings) and bounded undo/redo via full-graph snapshots plus a cursor; `graph-equality.ts` keeps no-op edits out of history. `dependencies.ts` `resolveDocument` recomputes positions and shapes in document order (creation order is topological) and returns the shape map; undefined geometry keeps its last values with `geometryValid: false` and recovers. A point whose part disappeared (fewer sides) moves to the nearest part. `planDeletion` removes helpers and dependents; free points a construction created for itself survive if something else uses them. `constructions.ts` builds every construction (`buildConstruction`) including a solid's helpers: side point C, base edge segment, the purple height point (`constraint.type === 'height'`), gray locked vertices (`'vertex'`, keyed by role + index, see `vertexSlots`). `editing.ts`: delete/hide/show-all rules, `setSideCount`/`syncVertexPoints` (vertex points follow type and side count; used extra ones are kept, undefined), `resolveAll` (resolve + vertex sync: the one call that brings the document up to date), `selectionTarget` (helpers select their owner). `definitions.ts` evaluates every `definition` with the current parameter values before shapes are resolved (parameters in dependency order, cycles fail); a field the user sets directly (drag, slider) drops its expression (`releaseField`). Dependencies include parameter names in definitions (`dependencyIds`), so deleting a parameter deletes what uses it. `redefine.ts` applies a card's `name: definition` text in place (same family of types only, no self-reference, renamed parameters are renamed inside expressions) and re-sorts the document into dependency order (`GeometryDocument.arrange`). `submit.ts` applies a command line as one history step; a name in use redefines that object. `file-format.ts`: the `.drw3` file (`{ app: 'drAW3D', format: 1, objects, camera }`), `parseDocument` checks types, IDs, references and coordinates; `GeometryDocument.reset` starts a fresh history (restored autosave) — an addition drAW2D does not have yet. Helper segments are named `kenar1`/`yarıçap1` so short names stay free for the user.
- `src/rendering/`: `scene-sync.ts` reconciles one view per object ID (created once, updated in place, disposed on removal; parameters have none) and applies the appearance fields; a solid's helper segment follows its owner's edge style. `views.ts` draws each shape kind with shared unit geometries; thick dashed/dotted lines are instanced short tubes/beads, solid edges use dashed line materials; a distance measure draws its shortest connection. `net-svg.ts` places a flat net on an A4 page in mm (1 unit = 1 cm, turned or shrunk only when it does not fit) and writes the SVG / print page. `materials.ts` caches materials by color; labels (angle degrees, measure values, names with the label setting) are HTML (`labels.ts`); `frame-renderer.ts` coalesces redraws into one `requestAnimationFrame` — the scene is drawn only on changes and while the camera's damping glides, never continuously.
- `src/app/app.ts` is the composition root: document, scene, camera, tools, toolbar, buttons, side panel, cards, command input, help, math keyboard, keyboard and pointer input. After any model change call `refresh()` (`resolveAll` → sync scene → cards → controls/buttons → request a frame). Slider and appearance edits run in a document edit session committed on release; playing a net (▶) is one such session. Files: `files.ts` hides the platform (desktop IPC dialogs, File System Access API, download/upload fallback); the document is autosaved to localStorage (`drAW3D.autosave`) a second after changes and restored on start; PNG export paints the WebGL canvas and the HTML labels onto one canvas. View state (camera direction, orthographic, axes, label mode, coordinates, hidden edges) lives in `ViewOptions` (`rendering/view-options.ts`), set from `ui/view-menu.ts` and kept in localStorage — never in the document. `camera-state.ts` holds a perspective and an orthographic camera and switches keeping the visible size; each frame passes `camera.eye()` to the scene so solids redraw their hidden edges. `object-cards.ts` builds each card (`describeCard`: definition, value lines, sliders `sideCount`/`unfold`/`value`), its edit text and the appearance settings it offers (`styleSpec`, `applyStyle`: defaults are stored as absent fields). Pointer input: a capture-phase `pointerdown` decides per press whether one finger / the left button may turn the camera (`OrbitControls.mouseButtons.LEFT` / `touches.ONE` set to `null` while a tool or a point drag owns the press); a second finger cancels the tool gesture and OrbitControls pinches. `camera-state.ts` is the single world ↔ canvas mapping (`Projector`) shared by hit testing, dragging and labels.
- `src/app/hit-test.ts`: pixel tolerance (mouse 10, pen 14, touch 22 px). Points win, then the nearest edge/curve unless a surface hides it, then the nearest surface along the pointer ray. Helpers are not pickable themselves (their owner has the same edges).
- `src/app/tools.ts` (`ToolController`): picked points are staged (new ones as document drafts); clicking an object creates a point on it; the finished object comes from `buildConstruction`. Structure tools (`STRUCTURE_STEPS`) also pick objects (lines, planes, spheres, a segment for the midpoint) and build through `prepareCommand` by the picked names. Mouse/pen act on press, a touch aims (preview follows) and acts on release. `select-tool.ts`: points before objects; free points drag horizontally (double tap toggles vertical), points on objects slide along their part, height points change the solid's height, vertices are locked; a drag is one history step and Escape reverts it.
- `src/ui/`: `tool-registry.ts` + `main-toolbar.ts` (drAW2D's grouped toolbar, same API; `window.drAW3DToolbar` is the test hook, `#mainToolbar[data-action]` the active tool), `toast.ts`, `title-bar.ts` (drawn only when the Electron preload API exists), `side-panel.ts` (right column / bottom sheet with Cebir and Araçlar tabs), `object-panel.ts` (cards keyed by object ID, newest first; element IDs `<id>-input`, `<id>-output`, `<id>-sliderA/B`, `<id>-edit`, `<id>-style`, `<id>-settings`, `<id>-color/size/lineStyle/opacity/label/faces/edges`, `<id>-visibility`, `<id>-remove`, `<id>-min/max/step`; IDs start with digits, so tests use `[id="…"]`), `command-input.ts`, `command-templates.ts`, `help-popup.ts`, `math-keyboard.ts`, `object-controls.ts` (floating side count and opening sliders: the prism/pyramid tool's side count, and the selected solid's sliders while the panel is hidden), `view-menu.ts` (`attachMenu` is the shared toolbar drop-down) and `file-menu.ts` (document, PNG and net export items; `#fileMenu`, items `#fileNew`, `#fileOpen`, `#fileSave`, `#fileSaveAs`, `#fileImage`, `#netTabs`, `#netSvg`, `#netPrint`, `#netPdf`).
- `window.drAW3DApp` is a read-only test hook (objects, selection, world → page coordinates, frame count, ground mode, view options, open file name).
- `electron/main.ts`: shell only, same pattern as drAW2D (sandboxed, `contextIsolation`, frameless window, `window.drAW3DDesktop.windowControls` over `window:*` IPC) plus `window.drAW3DDesktop.files` over `file:*` IPC: native open/save dialogs; the main process writes only to paths picked in a dialog this session and renders PDFs in a hidden window without scripts. It enables the SwiftShader WebGL fallback for machines without a usable GPU.
- Stylesheets are linked from `index.html`, not imported in TS. `toolbar.css` and `titlebar.css` are drAW2D's files unchanged — app-specific overrides go in `styles.css`. Icons are in `public/img`. Vite `base: './'` so the same build works under `file://`.

## Releases

GitHub Releases is the only place packages are published; madematik.com and the README link to it.

- **Build:** `.github/workflows/release.yml` builds the Linux packages (`.deb`, AppImage) on `ubuntu-latest` and the Windows `.exe` on `windows-latest`. Never cross-build Windows from Linux (wine) and never upload or replace release assets by hand. Before packaging the Linux job runs `npm test` (Playwright, WebGL on SwiftShader; the workflow installs Chromium). A failing step blocks the release.
- **Version:** `package.json` is the single source, so the local and GitHub versions are always the same. New release: `npm version patch` (or `minor`), then `git push --follow-tags`. The workflow fails if the tag `vX.Y.Z` differs from `package.json`.
- **Rebuild without a new version:** Actions → "Sürüm paketleri" → Run workflow replaces the assets of the current version (creates the release if missing). Build only, nothing published: `gh workflow run release.yml -f yayinla=false`, then `gh run download --name paket-Windows -D release`.
- **Asset names have no version:** `drAW3D-linux-amd64.deb`, `drAW3D-linux-x86_64.AppImage`, `drAW3D-win-x64.exe` (`build.artifactName` is `${productName}-${os}-${arch}.${ext}`), so `https://github.com/200709078/drAW3D/releases/latest/download/<name>` always fetches the newest release; the README "İndir" section and madematik.com use these links. Don't add the version back.
- **Notes and checksums:** `scripts/release-assets.mjs` writes `SHA256SUMS.txt` and the Turkish release notes (sizes, DEB dependencies and installed size read from the packages). Change the notes in the script, not on GitHub — the next run overwrites them.
- **Local copy:** `npm run dist*` output is for local testing only and differs byte-wise from the published files. To make `release/` match GitHub: `rm -rf release && gh release download vX.Y.Z -D release`, then `sha256sum -c SHA256SUMS.txt` inside `release/`.
- **Shared files:** the workflow and `scripts/release-assets.mjs` are identical copies in drAW, drAW2D and drAW3D (app name and version come from `package.json`) — change all three together. Actions: `checkout`/`setup-node`/`upload-artifact` v7, `download-artifact` v8 (Node 24).
- **Trigger quirk:** push a new or changed workflow file before the tag; a tag pushed in the same push as a new workflow did not trigger it.
- **Metadata:** license MIT (same text in all three repos), deb `Section: education`, `.desktop` categories include `Education`.

## Shared code with drAW2D

`graph-equality.ts`, the core of `geometry-document.ts` (drAW3D adds `get` and `arrange`), `frame-renderer.ts`, `main-toolbar.ts`, `toast.ts`, `title-bar.ts`, `side-panel.ts`, `command-input.ts`, `command-templates.ts`, `help-popup.ts`, `math.ts`, `toolbar.css`, `titlebar.css`, the panel/card/help/keyboard part of `styles.css`, the Electron shell and scripts are copies of drAW2D's modules with the same API (only app names differ). `object-panel.ts` and `math-keyboard.ts` keep drAW2D's structure with 3D settings and keys. Keep them in step; they will move into one shared package later (roadmap A1: deferred — if it happens, drAW, drAW2D and drAW3D move into one repository together).

## Tests

All tests are Playwright specs in `tests/`. Most import `src/` modules directly and run without a page (`geometry-*`, `document*`, `command-*`, `object-cards`, `app-tools`, `frame-renderer`); `app-tools.spec.ts` drives `ToolController`/`SelectController` through fake projectors (`tests/fixtures/top-down.ts`). `app-integration.spec.ts` and `panel-integration.spec.ts` drive the real app in Chromium (WebGL on SwiftShader) with mouse, CDP touch events, the command input, cards and the test hooks. Object colors are random, so tests check models and positions, never screenshots; use deterministic criteria (frame counts) instead of timing.

## Conventions

- Don't try to preserve existing code: rewrite whenever that makes it more efficient, correct or usable; the change must be tested and explained.
- `docs/yol-haritasi.md` lists the planned features and the user's requests — record new requests there with a date and do not implement any item until the user explicitly asks. `docs/ozellik-envanteri.md` is the behavior inventory from before the migration, with intentional changes noted.
- `dist/`, `dist-electron/`, `release/`, `test-results/` are build outputs and not committed.
